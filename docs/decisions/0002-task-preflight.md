# 0002：开工前按具体属性查重、检查认领并处理冲突

- 状态：本 PR 合入 `main` 后生效
- 日期：2026-11-15
- 补充：[0001](0001-agent-collaboration.md)
- 来源：维护者明确要求工作基于新代码、避免重复开发及抢活，并澄清颜色与大小无需互相确认，红色与绿色才属于同一属性的目标冲突

## 决定

开工、恢复和修改范围变化时，先获取并纳入最新主线，读取实际实现及相关任务、PR 和改动记录。用 `check_task_start.py` 核实当前任务包含检查时的最新主线；远端获取失败或任务落后时，不基于旧代码继续实施。

按“对象 + 具体属性/行为 + 预期效果”对照当前实现和公开认领。同目标已实现且核验满足请求时告知已完成，不重复改写；相同属性已被认领时不抢做；同一属性与别人已完成效果不同或互斥时，先摘要既有改动和本次差异，再取得用户知情确认。不同独立属性正常并行，即使位于同一文件。只有存在实际行为冲突时才升级协调。

将核对结果和继续依据写进任务/PR，开发中及合入前检查相关新增改动。已知情且具体的用户指令不重复索要确认。与新规则一致的既有原则继续有效；本决定细化 0001 的认领和冲突判断粒度。

## 边界

GitHub 严格基线检查约束合入，开工脚本约束主动执行它时的主线状态，均不能自动判定语义重复。公开认领不是原子锁，未公开的本地工作也不可见。因此这是一套可核验的预防与处理流程，不能承诺绝不冲突，也不得把不同属性的正常并行变成反复请示。
