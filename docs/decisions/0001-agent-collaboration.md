# 0001：以仓库和 GitHub 作为多 Agent 协作的共同依据

- 状态：本 PR 合入 `main` 后生效
- 日期：2026-11-15
- 来源：项目维护者要求建立多开发者、各自使用 Agent 的协作架构

## 背景

开发者的聊天记录、Agent 记忆和本地代码彼此不同。仅约定“开始拉代码、结束推代码”，仍会出现重复开发、接口不一致、覆盖别人的改动、测试结论丢失和“本地完成”被误报为“已交付”。

## 决定

1. 根目录 `AGENTS.md` 为统一规则入口，`CONTRIBUTING.md` 提供操作流程；不同 Agent 使用同一套仓库事实。
2. Issue 负责目标、范围、认领和交接，PR 负责实现、证据及审阅；人类任务负责人处理优先级与互斥需求。
3. 每个任务使用独立分支、优先独立目录，频繁读取实际最新内容并局部修改。共同修改同一文件并不自动意味着冲突。
4. 交付记录按 PR 拆分为独立文件，只追加；Git 与 PR 提供历史索引，不维护集中式可变任务表或单个总日志。
5. 长期共识经 PR 修改；涉及高风险行为需独立审阅。自动检查覆盖可机械判断的交付要求，游戏功能仍按范围实测。

## 影响与边界

- 不绑定模型供应商，不另建消息服务器、数据库或自动调度平台；未来有真实需要再增加。
- Issue 认领不是锁，CI 不是完整游戏验收，也不验证聊天里的声明真伪。负责人、审阅者仍需核对证据。
- 本次是规则体系的首次建立，可以用维护者明确委托代替已有 Issue；后续常规任务使用任务模板。
- 首次交付同时启用 `main` 分支保护，要求 PR、最新基线、自动检查和已解决讨论，并限制管理员直推、强推及删除。平台不强制审批人数，允许低风险作者自查；高风险独立审阅仍是公共规则。平台设置不会随仓库克隆迁移，边界见 `CONTRIBUTING.md`。
